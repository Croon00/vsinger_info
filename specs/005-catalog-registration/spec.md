## 사용자 시나리오와 검증

### US1 — 요청 아티스트와 채널의 등록 결과 확인 (P1)

1. **전제** 공식 출처와 검수 seed가 있는 요청 대상, **동작** 등록 미리보기·명시적 적용과 결과 조회, **기대 결과** 중복·소유권 충돌 없이 근거가 있는 명의와 채널을 확인한다.
2. **전제** 자료가 없거나 근거·입력이 불충분한 상태, **동작** 같은 경로 실행, **기대 결과** 원본 계약에 따라 빈 상태·입력 오류·보류를 구분하고 확인되지 않은 자료를 확정하지 않는다.

독립 검증은 plan.md의 관련 fixture와 원본 날짜별 실제 검증 기록을 대조한다.

## 예외와 경계 조건

빈 자료·잘못된 입력·소유권 충돌·중복·동시 실행·provider 실패·재시도·수동 교정·보관 상태 중 해당 경로의 조건을 원본 계약으로 확인한다. 과거 상태와 최신 계약이 다르면 날짜별 근거를 대조한다.

## 요구사항

### 기능 요구사항

- FR-001 공식 출처·고정 외부 ID·검수한 이름으로 등록하며 미확인 소속과 계정은 추정하지 않는다.
- FR-002 미리보기와 적용을 구분하고 기존 소유권·비활성 설정·감사 이력을 보존하며 충돌을 거부한다.
- FR-003 등록·활성화·작업 등록·실제 저장 완료를 각각 기록하며 후보·작업 수를 완료된 세트리스트 수로 표시하지 않는다.

### 주요 데이터

원본 문서의 아티스트·외부 계정·소유 관계와 해당 기능의 저장 자료·출처·감사 이력을 사용한다. 구체적인 저장 구조와 경로는 plan.md에 연결한다.

## 범위 경계

검수된 등록·자료 보완 이력을 묶는다. 관리 도구와 미요청 신규 등록·재수집은 후속 범위다.

## 완료 조건

- SC-001 등록한 아티스트·계정 ID에 공식 출처가 대응하고 미확인 항목은 보류된다.
- SC-002 같은 등록의 재실행에서 추가 생성이 0건이며 기존 소유권·활성 상태가 보존된다.
- SC-003 각 배치의 등록·대기·수집 결과를 날짜와 상태별로 확인할 수 있다.

## 가정과 의존성

AGENTS.md와 프로젝트 원칙, 기존 확정 계약을 따른다. 신규 기능 요구는 추가하지 않았다. 실제 DB 변경·재수집·전송·배포는 개별 요청 범위를 확인한다. Git 제외 보고서는 원본 위치를 참조하며 이번 정리에서 존재·내용을 확인하지 않았다.
