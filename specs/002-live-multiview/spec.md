## 사용자 시나리오와 검증

### US1 — 생방송과 예정 방송 탐색 (P1)

사용자는 /multiview에서 저장된 생방송·예정 방송을 확인한다.

1. **전제** 유효 snapshot, **동작** /api/streams·/api/stream-groups 조회, **기대 결과** 저장된 상태·그룹을 표시한다.
2. **전제** 만료·누락 자료, **동작** 조회, **기대 결과** 계약의 빈 상태를 표시한다.

독립 검증은 snapshot fixture로 목록·그룹·만료 경계를 확인한다.

### US2 — 예정 방송의 LIVE 전환 (P1)

운영자는 전체 검색과 진행 상태를 정해진 주기로 갱신한다.

1. **전제** Holodex 설정과 검색 기한 도달, **동작** 전체 검색, **기대 결과** 1시간 주기로 활성 대상 방송을 갱신한다.
2. **전제** 생방송 또는 예정 시각 도달 방송, **동작** 상태 확인 기한 도달, **기대 결과** 3분 간격으로 LIVE·대기·연기·종료/누락을 반영한다.
3. **전제** 상태 확인 실행, **동작** 저장, **기대 결과** 전체 검색 시각과 미래 예정 목록을 보존한다.

독립 검증은 가짜 시계·provider로 기한과 snapshot 보존을 확인한다.

### US3 — 멀티뷰 재생 (P2)

사용자는 방송을 선택해 영상·채팅을 연다. 실제 브라우저에서 선택·재생·채팅·자동재생 제한에 따른 동작을 확인한다.

## 요구사항

- FR-001 조회는 저장 snapshot을 사용하고 요청 중 provider를 호출하지 않는다.
- FR-002 Holodex 전체 검색 기본 주기는 3600초, 생방송·예정 시각 도달 방송 상태 확인 기본 주기는 180초다. 실제 운영 설정을 확인한다.
- FR-003 상태 확인은 전체 검색 기한·미래 및 시각 미정 예정 목록을 보존하고 live_checked_at을 갱신한다.
- FR-004 동일 provider lease로 중복 claim을 방지하고 재시작·실패·Retry-After에서 유예를 지킨다.
- FR-005 Holodex 예정 방송은 checked_at 기준 75분, 생방송은 live_checked_at(없으면 checked_at) 기준 15분 유효기간을 적용한다. YouTube fallback은 checked_at 기준 15분이다. 미래 관찰 시각과 만료 경계를 검증한다.
- FR-006 Holodex와 YouTube fallback의 설정·quota·상태를 각각 기록하고 일일 아카이브 수집 경계를 유지한다.
- FR-007 API·monitor·웹의 배포 revision과 실제 브라우저 결과를 기록한다.

## 예외와 경계 조건

예정 시각 없음·연기, provider 누락, 종료, snapshot 만료 경계, 다중 인스턴스, 재시작 직후 검색, 인증 실패·429, 재생·자동재생 제한을 검증한다.

## 범위 경계

Holodex 미등록 채널의 추가 discovery와 최근 업로드 밖 미발견 예약 방송 보완은 후속 작업이다. 대상 확대와 예산 변경은 해당 요구사항을 먼저 확정한다.

## 완료 조건

- SC-001 fixture에서 3600초·180초 경계, 상태 전환·검색 시각 보존·lease·실패 유예를 확인한다.
- SC-002 fixture에서 예정 방송 75분·생방송 15분 만료와 관찰 시각 선택, 조회 중 provider 호출 0회를 확인한다.
- SC-003 실제 설정·revision·관찰 기간·요청량·상태 갱신·오류·유예를 기록하고 FR-002~004에 대조한다. 관찰 기간은 실행 환경과 provider 한도에 맞춰 계획한다.
- SC-004 배포 웹의 선택·영상·채팅·자동재생 제한 결과를 브라우저와 날짜로 기록한다.
