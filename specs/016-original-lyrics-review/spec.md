# 오리지널 곡 가사 후보 수집과 검토 후 등록

작성: 2026-11-25 · 상태: 후보·직접 입력 파일 생성 완료, 검토·등록 대기

## 사용자 시나리오

- US1: 전제 — 오리지널 곡의 공식 영상 설명란이나 댓글에 가사가 있다. 동작 — 내보내기 스크립트를 실행한다. 기대 결과 — 출처 URL·원문과 함께 가사 후보가 검토 파일에 담기고 DB는 바뀌지 않는다.
- US2: 전제 — 가사를 찾지 못한 오리지널 곡이 있다. 동작 — 같은 실행에서 직접 입력 파일을 받는다. 기대 결과 — 곡·아티스트·녹음 ID·영상 URL과 빈 가사 칸이 있는 목록을 받는다.
- US3: 전제 — 검토자가 항목을 고치고 `approved: true`로 표시했다. 동작 — 가져오기 스크립트를 `--apply`로 실행한다. 기대 결과 — 승인 항목만 출처 문서와 함께 `recording_lyrics`에 저장되고 기존 가사는 바뀌지 않는다.
- US4: 전제 — 오리지널 곡에 가사가 없고 편집자가 편집 키를 갖고 있다. 동작 — 곡 탐색 또는 아티스트의 오리지널 곡 탭에서 가사 등록을 눌러 저장한다. 기대 결과 — 영상이 없는 곡도 등록할 수 있고, 기존 목록에서 가사를 보고 수정할 수 있다.
- US5: 전제 — 오리지널 녹음에 활성 가사가 있다. 동작 — 편집자가 가사 수정을 눌러 기존 값을 확인하고 수정한다. 기대 결과 — 새 가사가 조회되고 이전 값과 출처가 보존된다. 가사가 먼저 변경된 경우 최신 값을 확인하라는 응답을 받는다.

## 요구사항과 완료 조건

- FR-001: 대상은 `/api/explore/songs?kind=original`과 같은 오리지널 목록이다. 같은 영상을 공유하는 녹음은 한 항목으로 묶고 모든 녹음 ID를 기록한다.
- FR-002: 공식 영상 설명란의 가사 블록을 먼저 찾고, 없으면 관련도순 상위 댓글 100개 중 가사라고 알리거나(歌詞·Lyrics) 곡명으로 시작하는 댓글만 후보로 삼는다. 채널 본인 댓글을 우선한다.
- FR-003: 후보는 출처 종류·URL·외부 ID·채널 본인 여부·추출 방식·원문 전체를 함께 남긴다. 팬 댓글은 정확도를 보장하지 않으므로 표시해 둔다.
- FR-004: 내보내기는 DB를 쓰지 않는다. 할당량·일시 오류가 나면 일부만 담긴 파일을 쓰지 않고 중단한다.
- FR-005: 가져오기는 기본 미리보기이며 `--apply`에서만 한 트랜잭션으로 쓴다. 승인 항목만 처리하고, 보관된 녹음이나 이미 가사가 있는 녹음은 건너뛴다. 출처는 `source_documents`에 내용 해시로 중복 없이 남긴다.
- FR-006: 번역·독음은 검토자가 채운 값만 저장한다. 이번 범위에서 자동 번역·독음 생성은 하지 않는다.
- FR-007: 웹은 원문과 선택 항목인 번역·독음·출처 URL을 같은 모달에서 등록·수정한다. 등록은 대표 녹음, 수정은 가사가 있는 녹음 한 건을 대상으로 한다.
- FR-008: 서버는 가사 편집 키, 활성 오리지널 녹음 여부, 버전을 검증한다. 저장은 이전 가사와 출처를 참조할 수 있는 이력을 남기며 동일 내용 재시도에도 중복 이력을 만들지 않는다.
- SC-001: 가져온 가사는 기존 `/api/recordings/{id}/lyrics`와 발매곡 `has_lyrics`로 바로 공개된다는 점을 운영 문서에 명시한다.
- SC-002: 표본 판정과 추출 결과의 일치, fixture 테스트, 전체 내보내기 결과를 기록한다.
- SC-003: 격리 DB에서 등록·수정·버전 충돌·커버 제외·이력 보존을 검증하고, 데스크톱·모바일에서 모달의 신규 등록과 기존 값 수정을 검증한다.

근거: 2026-11-24~25 사용자 요청(설명란·댓글 가사 수집, 남은 곡 직접 입력 목록). 가사 공개의 저작권·YouTube API 데이터 보관 정책 위험은 대화에서 안내했으며 공개 여부는 검토자가 항목별로 결정한다.
