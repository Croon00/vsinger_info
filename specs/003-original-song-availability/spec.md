# 오리지널 곡 조회의 분류 파일 누락 복구

작성: 2026-11-21. 근거: 운영 API HTTP 500과 사용자가 제공한 분류 파일 `FileNotFoundError` 로그.

## 요구사항

- FR-001: 검수된 분류 자료를 내용·출처 변경 없이 앱 내부 배포 리소스로 보존한다.
- FR-002: 분류 파일이 없어도 분류 필터 없는 오리지널 곡 조회는 DB 목록을 반환한다.
- FR-003: 파일 누락 중 장르·분위기 필터를 요청하면 HTTP 503을 반환하며, 0건으로 오인시키지 않는다.
- FR-004: 파일 복구 후 다음 조회는 태그를 다시 읽는다. 조회에서 수집·DB 변경·외부 전송을 실행하지 않는다.

## 인수 시나리오

- US-001: 전제: 분류 파일이 없다. 동작: 기본 오리지널 목록을 조회한다. 기대 결과: HTTP 200과 등록된 곡, 빈 태그를 반환한다.
- US-002: 전제: 분류 파일이 없다. 동작: 장르 또는 분위기를 지정한다. 기대 결과: HTTP 503을 반환한다.
- US-003: 전제: 누락된 분류 파일을 복구했다. 동작: 다시 조회한다. 기대 결과: 검수된 태그를 반환한다.

## 완료 조건

- SC-001: 위 인수 시나리오와 기존 분류 schema·조회 계약 테스트를 통과한다.
- SC-002: 새 코드와 리소스를 배포한 운영 사이트의 기본 조회·분류 필터를 확인한다. 로컬 통과와 구분한다.
