# 기능 명세 — 프로필 이미지 저장·초기 이미지 작업

정리일 2026-11-18 · 기능 식별자 `004-avatar-storage` · 상태 기존 작업 이관, 후속 확인 남음

## 입력과 근거

2026-11-21 사용자 요청 보완: Figaro(941)·shin(942)의 프로필 이미지 표시 실패를 조사하고 기존 사진을 복구한다. 전제: 원본과 작은 변형은 정상, 대표 512px 파일은 404. 동작: 저장 원본과 기존 변형 일치를 검증하고 누락 파일만 복구한다. 기대 결과: 기존 사진·URL을 유지하며 128/256/512px 모두 공개 GET·이미지 검증을 통과한다(SC-001~003).

사용자 요청에 따라 기존 요구·구현·검증 기록을 소급 정리했다. 수치와 완료 기록은 원본 날짜에 적용한다. 이번 정리에서는 운영 상태를 재측정하지 않았다.

- [avatar-storage](../../docs/avatar-storage.md)

## 사용자 시나리오와 검증

### US1 — 프로필 이미지 조회와 초기 채움 (P1)

1. **전제** 공식 owner 계정과 빈 프로필 이미지, **동작** 초기 이미지 작업 처리 후 화면 조회, **기대 결과** 검증한 이미지와 크기별 변형이 표시된다.
2. **전제** 자료가 없거나 근거·입력이 불충분한 상태, **동작** 같은 경로 실행, **기대 결과** 원본 계약에 따라 빈 상태·입력 오류·보류를 구분하고 확인되지 않은 자료를 확정하지 않는다.

독립 검증은 plan.md의 관련 fixture와 원본 날짜별 실제 검증 기록을 대조한다.

## 예외와 경계 조건

빈 자료·잘못된 입력·소유권 충돌·중복·동시 실행·provider 실패·재시도·수동 교정·보관 상태 중 해당 경로의 조건을 원본 계약으로 확인한다. 과거 상태와 최신 계약이 다르면 날짜별 근거를 대조한다.

## 요구사항

### 기능 요구사항

- FR-001 원본과 128·256·512 WebP 변형을 저장·검증한 뒤 대표 URL을 반영하고 크기에 맞게 지연 로딩한다.
- FR-002 공식 owner 관계의 빈 이미지 작업을 예약하고 YouTube→X 후보 순서·lease·재시도·provider 대기를 적용한다.
- FR-003 기존·실행 중 수동 지정 이미지를 보존하고 반영 직전 소유 관계를 재확인한다. 조회는 작업을 생성·실행하지 않는다.

### 주요 데이터

원본 문서의 아티스트·외부 계정·소유 관계와 해당 기능의 저장 자료·출처·감사 이력을 사용한다. 구체적인 저장 구조와 경로는 plan.md에 연결한다.

## 범위 경계

초기 이미지와 명시적 교체를 포함한다. admin-web 연동과 정기 교체는 후속 범위다.

## 완료 조건

- SC-001 대표 URL과 변형 파일의 공개 응답·내용·캐시가 저장 계약과 일치한다.
- SC-002 재실행·동시 처리의 중복 교체가 0건이고 실패 단계와 대기·재시도 상태가 남는다.
- SC-003 수동 이미지와 변경된 소유 관계가 보호되고 조회로 업로드가 발생하지 않는다.

## 가정과 의존성

AGENTS.md와 프로젝트 원칙, 기존 확정 계약을 따른다. 신규 기능 요구는 추가하지 않았다. 실제 DB 변경·재수집·전송·배포는 개별 요청 범위를 확인한다. Git 제외 보고서는 원본 위치를 참조하며 이번 정리에서 존재·내용을 확인하지 않았다.
