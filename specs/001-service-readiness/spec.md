## 사용자 시나리오와 검증

### US1 — 저장된 음악 자료 조회 (P1)

사용자는 신규 DB의 아티스트·라이브·가창·앨범을 조회한다.

1. **전제** 저장 자료, **동작** 검색·상세 조회, **기대 결과** /api 계약에 맞는 자료와 출처를 표시한다.
2. **전제** 미등록 자료, **동작** 조회, **기대 결과** 빈 상태를 표시하고 수집 작업을 시작하지 않는다.

독립 검증은 격리 DB의 수집 결과를 실제 API로 조회하고 웹 fixture와 대조한다.

### US2 — X 새 글 URL 알림 (P1)

서버 사용자는 허용된 route에서 새 글 URL을 한 번 받는다.

1. **전제** 신규 계정과 유효 route, **동작** 새 글 수집, **기대 결과** 원문·외부 ID·출처를 저장하고 해당 route에 URL을 전달한다.
2. **전제** 동일 글 재수집 또는 route 없음, **동작** 재실행, **기대 결과** 중복 알림을 만들지 않고 처리 결과를 기록한다.

독립 검증은 가짜 provider·sender로 중복·권한 조건을 재현한다.

### US3 — 독립 YouTube·Spotify 수집 (P1)

운영자는 등록 계정의 자료와 작업 상태를 확인한다.

1. **전제** 활성 신규 계정, **동작** 수집 작업, **기대 결과** 신규 DB에 영상·음악·출처를 저장한다.
2. **전제** 실패·재시도·공동 크레딧·수동 교정, **동작** 재개, **기대 결과** 소유권과 교정을 보존하며 중복을 방지한다.

## 요구사항

- FR-001 조회와 worker는 신규 DB 공통 설정을 사용하고 기존 DB를 읽기 전용으로 보존한다.
- FR-002 /api는 저장 자료만 반환하고 페이지·필터·정렬·빈 상태 계약을 따른다.
- FR-003 X는 external_accounts 기준 원문 수집과 source_items·route별 delivery 중복 방지를 적용한다.
- FR-004 route 부재·권한 부족·결과 불명 전송·재시도를 기록하고 무조건 재전송하지 않는다.
- FR-005 독립 YouTube와 등록 Spotify 수집은 출처·외부 ID·소유권·수동 교정을 보존한다.
- FR-006 worker 상태·실패·설정 누락을 /ready와 운영 기록에서 확인한다.
- FR-007 실제 주기·provider 한도·서비스별 writer·배포 revision을 기록한다.

## 예외와 경계 조건

계정 비활성화, lease 만료, quota·인증 오류, 전송 성공 후 이력 저장 실패, 수동 교정, 첫 수집의 과거 글을 포함한다. 처리 정책은 원본 보완 단계 문서를 따른다.

## 범위 경계

admin-web·관리 API 개편, 노래방, 가사·번역·독음 worker, 추가 과거 자료 이전은 후속 범위다. X 분류·봇 명령·X→YouTube와 Google Calendar는 제거·격리 방침을 따른다.

## 완료 조건

- SC-001 격리 DB→가짜 provider→저장→실제 /api 검증에서 중복 저장·전송 0건과 기존 계약 호환을 확인한다.
- SC-002 운영 활성 대상이 확인된 설정 주기 내 처리되고 신규 자료가 DB·웹에 나타난 근거가 있다.
- SC-003 요청 범위의 실제 X URL이 올바른 route에 한 번 전달되고 과거 성공 알림·첫 수집 과거 글의 재전송이 0건이다.
- SC-004 기존 DB 쓰기와 금지된 실행 경로 호출이 0건이다. 날짜·revision·설정·관찰 기간·실패·생략을 기록한다.

## 현재 근거

보완 A~F와 선택 이전 완료는 원본 문서의 과거 결과다. X provider 오류·Discord 실제 전송·Railway 실행 상태는 미완료 작업으로 추적하며 실행 때 현 상태를 다시 확인한다.
