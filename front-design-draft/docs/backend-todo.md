## 향후 버전: 곡을 기준으로 탐색·통계 (사용자 요청)

현재 버전의 화면 구현 범위에는 포함하지 않되, 조회 API와 DB 관계 재설계 시 고려한다.

- 목표: 곡 목록 및 상세, 해당 곡을 많이 부른 아티스트, 월별 가창 추이, 곡 정보.
- 기존 songs는 YouTube/Spotify/가사 중심이며, youtube_song_performances에는 이를 참조하는 song_id가 없다. 제목 문자열만으로 동일 곡을 집계하지 않는다.
- 곡의 공통 식별자와 원어/한국어/검색 별칭을 설계한다. 곡 자체와 Spotify 발매 트랙·YouTube 영상·편곡/녹음 버전은 별도 개념으로 연결한다.
- 가창 기록에 nullable 곡 식별자와 명확한 가창자 관계를 추가하는 점진적 이전을 검토한다. 원본 제목·원곡 아티스트 표기는 보존하고, 불확실한 연결은 미확정으로 남긴다.
- 원곡 아티스트와 가창 아티스트의 역할을 분리한다. 원곡 아티스트는 추적 대상이 아니어도 등록 가능해야 하며 공동 원곡 아티스트·합동 가창 관계를 고려한다.
- 기존 가사 song_id 참조를 깨뜨리지 않도록 확장 또는 별도 canonical 곡 테이블 연결 후 이전한다. 기존 데이터 일괄 덮어쓰기/제목만으로 자동 병합하지 않는다.
- 집계 기준: 한 번의 가창을 기본 단위로 정의하고, 메들리·반복·부분 가창·합동 가창·재업로드 처리 및 버전 합산 기준을 명시한다.
- 월별 추이는 가창 횟수와 별개로 전체 수집 가창 대비 비율을 제공할지 검토한다. 수집량 증가를 곡 인기 상승으로 오인하지 않도록 기준을 설명한다.
- 현재 단계에서는 관계와 이전 경로만 준비한다. 곡 상세 UI·완성된 통계 API·별도 검색 시스템은 이후 범위다.
