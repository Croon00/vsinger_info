## 2. 디자인 방향

음악을 찾고 좋아하는 아티스트에게 빠르게 이동하는 개인 시작 화면을 중심으로 구성한다. 홈은 큰 검색창과 즐겨찾기에 집중하고, 탐색에서는 아티스트 이미지와 이름을 크게 사용한다.

공식 프리셋 해석 코드 기준 `a2vfHFI`는 Luma, Neutral 기본색/테마, Inter 본문과 상속하는 제목 폰트, Lucide 아이콘, 기본 반경, subtle 메뉴 강조 구성이다. 실제 CLI 초기화에 프리셋 코드를 전달해 적용했으며 생성된 `components.json`과 CSS 토큰을 기준으로 삼는다.

- 배경·텍스트·테두리·선택 상태는 프리셋의 의미 기반 색상 토큰을 사용한다.
- 사진과 앨범 아트를 주된 시각 요소로 사용한다.
- 한글·일본어를 읽기 위한 CJK 폰트 fallback을 추가하되 Inter 기본 설정을 유지한다.
- 카드·입력·탭·팝업은 shadcn-vue 컴포넌트의 변형과 조합을 사용한다.
- 초기 브랜드 표기는 `schedule_music`으로 두고, 별도 로고 디자인은 필수 범위에 넣지 않는다.

## 3. 화면별 설계

프로필의 메인 이름은 원어(`name`), 서브 이름은 한국어(`display_name`)로 통일한다. 홈·탐색·검색 카드와 상세 프로필에 적용하며 영문 검색 별칭(`roman`)은 검색용으로 유지한다. 홈 compact 카드의 두 이름 사이 여백은 1px로 줄인다.

홈 즐겨찾기에서는 삭제용 하트 버튼을 표시하지 않는다. 즐겨찾기 변경은 탐색·아티스트 상세에서 한다. 모바일 홈은 한 줄 4명, 가로 간격 12px·세로 간격 24px, 사진 최대 88px, 사진과 이름 간격 8px로 표시한다. PC 홈의 6열은 유지한다.

아티스트 카드 이름은 PC 15px·모바일 14px로 통일하고 이름 길이에 따른 자동 축소는 사용하지 않는다. 이름과 보조 이름은 한 줄 말줄임, 제목·보조 줄 높이는 고정하며 하트는 축소되지 않는 독립 영역을 유지한다. 이름 툴팁은 사용하지 않고 전체 이름은 상세 화면에서 확인한다. 공통 카드를 쓰는 홈·검색도 말줄임을 적용하되 compact 글자 크기는 유지한다.

탐색 프로필 격자: 화면 폭 768px 이하는 한 줄 3명, 769~1200px는 4명, 1201~1439px는 5명, 1440px 이상은 최대 6명이다. 모바일 가로 간격은 12px이며 이름 옆에 즐겨찾기를 유지한다. 긴 이름은 말줄임 처리해 버튼이 다음 줄로 내려가지 않게 한다.

2026-09-16 내비게이션 수정: PC 사이드바는 텍스트 16px·아이콘 24px, 769~1023px의 아이콘 전용 단계는 아이콘 28px·버튼 56px로 표시한다. 모바일은 메뉴 텍스트를 숨긴 44px 아이콘 버튼 4개와 이동하는 선택 배경으로 구성한다. 각 링크의 접근성 이름·`aria-current`·키보드 포커스는 유지한다. 선택 배경은 250ms로 이동하고 눌렀을 때 크기가 살짝 줄어들며, reduced-motion에서는 전환을 제거한다.

2026-09-15 캘린더 개선: Luma Card 안에 월 이동·일정 종류 필터·날짜 격자를 모으고, 아티스트 범위는 페이지 제목 옆에 둔다. PC 날짜 셀에는 공연/생일 Badge를 표시하고 클릭 시 상세로 이동한다. 모바일은 48px 높이 날짜 셀과 아이콘 표식으로 압축한다. 일정 목록은 날짜·프로필·종류·제목·장소 순으로 읽히는 행으로 구성하며, 비어 있는 날짜 목록을 처음부터 별도 표시하지 않는다. 가상 공연과 한국 시간 안내는 달력 하단에 유지한다.

### 홈과 통합검색

- 검색창 아래 즐겨찾기 영역을 두어 브라우저 시작 화면처럼 사용한다.
- 즐겨찾기가 없을 때는 탐색으로 이동하는 명확한 안내를 보여준다.
- 제안: 초기 데모에 즐겨찾기 6명을 넣고, 변경 내용은 새로고침 후에도 유지한다.
- 검색 대상은 아티스트 이름과 세트리스트의 원곡명·원곡 아티스트명이다. 라이브 제목·공연명·독립 디스코그래피 검색은 포함하지 않는다.
- 결과는 `아티스트`와 `세트리스트` 두 섹션으로 나눈다. 아티스트 결과는 상세 페이지로, 세트리스트 결과는 해당 라이브의 노래 시작 시점으로 이동한다.
- 세트리스트 결과 한 건은 특정 라이브에서 부른 한 곡이다. 원곡명, 원곡 아티스트, 부른 아티스트, 라이브 제목, 방송일, 시작 타임스탬프를 보여준다. 같은 곡을 다른 라이브에서 부른 경우 각각 결과가 된다.
- 기본은 한 검색어를 대상 필드 중 하나라도 포함하는 결과로 찾는다. 결과에서 부른 아티스트·원곡 아티스트를 선택해 좁힐 수 있도록 제안한다.
- 검색어는 URL에 보존하고, 검색 중·결과 없음·오류·재시도를 모두 다룬다.
- 한글 입력 조합 중에는 검색을 확정하지 않는다. 등록된 한국어·일본어·영문 이름 별칭으로 검색한다.

- 곡 목록은 원어/한국어 곡명·원곡 아티스트로 검색하고 많이/적게/최근/오래전에 부른 순으로 정렬한다. 날짜 정렬은 각 곡의 마지막 가창일 기준이다.
- 10곡씩 페이지 이동한다. 검색·정렬 변경 시 1페이지로 돌아간다. 순위는 전체 가창 횟수 기준 공동 순위이며 검색/정렬로 바뀌지 않는다.
- 원곡 아티스트 전체를 횟수순으로 10명씩 페이지 이동한다. 곡 페이지와 독립적으로 동작한다. 가창 횟수와 전체 가창 횟수 대비 비율을 숫자·가로 막대로 표시하며 페이지별로 비율을 다시 계산하지 않는다.
- PC는 곡 목록과 원곡 아티스트를 나란히, 1200px 이하에서는 세로 배치한다. 모바일 최근 가창일은 곡명 아래 표시한다. 모바일 상세 탭은 텍스트 중심으로 네 탭을 한 줄에 배치한다.
- 페이지별 콘텐츠를 같은 CSS Grid 영역에 배치해 가장 높은 페이지의 높이를 유지한다. 비활성 페이지는 visibility:hidden·inert·aria-hidden으로 숨긴다. 목록 영역의 스크롤 앵커 보정을 끄고, 화면 너비·폰트·검색·정렬 변경 시 브라우저가 자연 높이를 다시 계산한다. 마지막 페이지도 버튼 위치와 문서 높이를 유지한다.
- 정렬은 shadcn-vue Select를 사용한다. 두 목록의 페이지 네비게이션은 중앙 정렬하며 현재/전체 페이지 설명 텍스트는 표시하지 않는다.
- 데이터가 없는 아티스트는 빈 상태를 보여준다. 현재 HACHI는 아카이브 3개 중 세트리스트 1개가 등록되어 14회/14곡/11명이다.

**오리곡 탭**

- 앨범·싱글의 커버, 이름, 발매일을 보여주고 선택한 릴리스의 트랙 목록을 PC에서는 오른쪽, 모바일에서는 바로 아래에 표시한다.
- 각 트랙에 가사 버튼과 확인된 재생 서비스 링크를 둔다.
- 가사 팝업은 원문·한국어 번역·발음을 켜고 볼 수 있도록 설계한다. 현재 API에 세 필드가 모두 존재한다.
- 샘플 가사임을 팝업에 표시한다. 가사가 없는 트랙은 없다는 상태를 보여준다.

**공연 정보 탭**

- 상단: 예정 오프라인 공연을 가까운 날짜순으로 표시한다.
- 하단: 과거 공연을 최신순 연도별 타임라인으로 표시한다.
- 공연 팝업: 제목, 아티스트, 날짜·시간, 장소, 가격, 티켓 안내, 공식 링크.
- 예정 공연 없음, 장소 미정, 시간 미정도 유효한 상태로 다룬다.
- 실물 장소가 있는 하이브리드 공연은 오프라인 공연으로 포함하고 온라인 부분은 별도 일정으로 만들지 않는다.

### 라이브 뷰어

- PC: 좌측 큰 영상, 우측 세트리스트. 모바일: 영상 아래 세트리스트.
- 실제 YouTube 임베드 재생을 사용한다. API 데이터는 계속 mock이다.
- 재생 가능한 공식 영상과 검증한 시점을 데모에 사용한다. 세트리스트 클릭으로 해당 시점으로 이동하고, 재생 시간이 변하면 현재 곡을 갱신한다.
- 자동 재생은 기본으로 끈다. 영상 준비 전에는 탐색을 대기하고 실패 시 안내와 YouTube 원문 링크를 제공한다.
- 페이지를 벗어나면 재생을 정리한다. 미니 플레이어·지속 재생·현재 곡 가사 패널은 1차 범위에서 제외한다.

### 캘린더

- 오프라인 공연과 생일만 다룬다. 종류별 표식은 색상뿐 아니라 아이콘·텍스트로도 구분한다.
- 제안: 즐겨찾기 아티스트를 기본 범위로 하고 전체 보기로 전환 가능하게 한다.
- PC: 월간 달력 + 선택 날짜의 일정 목록. 모바일: 간결한 월간 달력 + 월/선택 날짜 중 하나의 일정 목록.
- 많은 일정이 있는 날짜는 일부만 노출하고 나머지 개수를 표시한다. 날짜 선택 시 전체 항목을 볼 수 있다.
- 공연은 시간대가 포함된 시각으로 저장하고 기본 표시 시간대는 Asia/Seoul로 한다. 공연 상세에는 필요하면 현지 시간대를 함께 표시한다.
- 생일은 시각 없는 월·일의 매년 반복 일정으로 다룬다. 공식 날짜를 확인하지 못한 경우 데모 날짜임을 표시하거나 미상으로 남긴다.
- 데모 일정은 재현 가능한 고정 기준일과 상대 날짜 규칙으로 구성한다. 시간이 지나도 예정·과거 공연을 둘 다 확인할 수 있게 한다.

## 4. 반응형과 접근성

- 제안 breakpoint: 1024px 이상 전체 사이드바, 768~1023px 좁은 사이드바, 767px 이하 하단 독.
- 독은 아이콘과 텍스트를 함께 사용하고 safe area 및 본문 하단 여백을 확보한다.
- 입력 중 가상 키보드와 독이 겹치지 않게 처리한다.
- PC의 공연·가사 팝업은 Dialog, 모바일은 Drawer를 사용한다. 긴 내용은 패널 내부에서 스크롤한다.
- 팝업은 제목, 키보드 조작, 포커스 복귀를 갖춘다. 뒤로가기로 닫을 때 원래 화면과 스크롤을 유지한다.
- 클릭 영역 44px 이상을 목표로 하고, 선택·즐겨찾기 상태를 스크린리더에 전달한다.
- 390px, 768px, 1440px 화면에서 확인하고 긴 일본어 제목, 이미지 실패, 200% 확대도 점검한다.

## 5. 모션 적용 계획

shadcn-vue의 컴포넌트 구조, 상태, 접근성 처리를 유지하면서 transitions-dev 지침 중 호환되는 부분을 적용한다.

| 상호작용 | 적용 방향 |
| --- | --- |
| 가사·공연 팝업 | modal open/close, 열기 250ms·닫기 150ms 기준 |
| 아티스트 탭 | tabs sliding, 선택 표시의 이동 |
| 즐겨찾기 | icon swap 중심의 작은 상태 변화 |
| 목록 로딩 | shadcn Skeleton + 로딩 완료 시 content reveal |
| 목록에서 상세 이동 | 8px 내외의 짧은 진입 변화, 기존 레이아웃 안정성 우선 |

duration/easing은 공통 모션 토큰으로 관리한다. 색상·타이포그래피·반경을 transitions-dev 값으로 덮지 않는다. 모든 동작은 reduced-motion 환경에서 정적 전환으로 대체한다. 컴포넌트 고유 모션과 중복 실행하지 않는다.

## 6. API 기준과 목업 구조

Vue 3 + TypeScript + Vite + Vue Router + Tailwind CSS + shadcn-vue를 제안한다. 데이터 계층은 `fetch` 클라이언트와 MSW로 분리한다. MSW는 브라우저 요청을 가로채 목업 응답을 제공하므로, UI가 fixture 파일에 직접 의존하지 않게 구성할 수 있다.

| 기능 | 확인한 기존 API | 초안 처리 |
| --- | --- | --- |
| 아티스트 목록·상세 | `GET /api/artists`, `/api/artists/{artist_id}` | `ArtistWithSources` 구조 재현 |
| 주요 링크 | 아티스트 응답의 `sources`, `representative_youtube_url` | 표시용 링크로 매핑 |
| 라이브 목록·상세 | `GET /api/youtube-lives`, `/api/youtube-lives/{archive_id}` | 응답 fixture와 뷰 모델 분리; 아티스트 필터는 현재 `artist_name` |
| 세트리스트 검색 | `GET /api/youtube-performances` | `artist_name`, `song_title`, `original_artist` 배열 query 계약 참고 |
| 디스코그래피 | `GET /api/spotify/artists/{artist_id}/discography` | 앨범·싱글 목록 fixture |
| 트랙 목록 | `GET /api/spotify/albums/{album_id}` | `tracks`를 트랙 행으로 표시 |
| 가사 | `GET /api/songs/{song_id}/lyrics` | 원문·번역·발음 필드 재현 |
| 공연 | `GET /api/event-candidates` | 후보 응답을 표시용 공연 모델로 매핑 |
| 통합검색 집계·즐겨찾기·생일·환경설정 | 검토한 현재 라우터에는 전용 API 없음 | 아티스트·세트리스트 결과 집계 및 초안 확장 계약으로 명시 |

백엔드 참조 파일: `../app/api/routers/{artists,youtube,songs,spotify}.py`, `../app/core/models.py`, `../app/integrations/spotify.py`의 공개 응답 모델. 프론트 구현 파일은 읽지 않았다.

`ArtistWithSources`에는 별도 생일 필드가 없으므로 이를 기존 계약으로 가장하지 않는다. 아티스트의 정수 ID, Spotify ID, song_id 간 연결은 adapter에서 관리한다. 공연 후보는 확정 공연 데이터와 의미가 다르므로 초안의 `Concert` 모델을 별도 정의한다.

통합검색의 한 입력창에서 여러 필드를 동시에 부분 일치로 찾는 방식은 초안용 검색 계약이다. 현재 `/api/youtube-performances`의 개별 조건 파라미터가 그대로 이 동작을 제공한다고 가정하지 않는다. 기존 응답을 재현한 fixture에 대한 검색 집계를 `/api/draft/search`에서 담당한다.

제안 디렉터리:

```text
src/
  app/             # router, providers, 앱 초기화
  components/ui/   # CLI로 추가한 shadcn-vue 컴포넌트
  components/      # 앱 내비게이션, 아티스트 카드, 공통 팝업
  pages/           # Home, Explore, Artist, LiveViewer, Calendar, Settings, Search
  api/             # fetch client, 계약 타입, 응답 adapter
  mocks/           # MSW handlers, fixtures, 데모 날짜, 상태 시나리오
  composables/     # 즐겨찾기, 테마, 지역 저장 상태
  assets/          # 앱 스타일과 로컬 자산
```

- 기존 계약 재현은 `/api/*`, 초안 확장 계약은 `/api/draft/*`로 구분한다.
- 모든 앱 API 요청은 MSW 준비 이후 실행한다. 처리되지 않은 앱 API는 실제 서버로 전달하지 않고 실패로 드러낸다.
- 즐겨찾기·테마·선택 범위는 프로젝트 전용 localStorage 키에 저장한다.
- 기본 지연은 일정하게 두고 empty/error/slow 시나리오는 URL 또는 개발 도구로 선택해 재현한다. 무작위 오류는 넣지 않는다.
- 설정에 제품 기능처럼 디버그 항목을 노출하지 않는다.
- 제안 데이터 규모: 아티스트 12명, 대표 아티스트 3명의 라이브·디스코그래피·공연 풍부하게 구성, 나머지는 빈 상태도 확인할 수 있게 구성한다.
- 검색 검증을 위해 같은 원곡을 여러 라이브·아티스트가 부른 세트리스트 사례를 포함한다. 실제 영상과 연결한 곡과 시작 시점은 확인된 메타데이터를 사용한다.
- 공식 이미지의 출처 URL과 영상 URL은 fixture 메타데이터에 기록한다. 공식 사실과 가상 데이터를 명시적으로 구분한다.

## 7. 경로와 이동

| 경로 | 화면 |
| --- | --- |
| `/` | 홈 |
| `/explore?q=...` | 탐색 |
| `/artists/:artistId?tab=lives` | 아티스트 상세; 탭 `lives`, `originals`, `concerts` |
| `/lives/:archiveId?t=...` | 라이브 뷰어 및 선택 재생 시점 |
| `/calendar?month=YYYY-MM-DD` | 캘린더; month 값은 월의 첫날 날짜 |
| `/settings` | 설정 |
| `/search?q=...` | 통합검색 결과; 주 메뉴는 추가하지 않음 |

공연·가사 팝업은 기존 페이지에 query 상태를 추가해 열고, 직접 접근·새로고침·뒤로가기를 지원한다. 주 메뉴의 활성 표시는 상세/뷰어에서도 탐색 문맥을 유지한다.

## 8. 구현 순서와 검증

1. 확정 답변을 이 문서에 반영한다. 독립 앱 초기화 때 `shadcn-vue init --preset a2vfHFI --template vite`를 사용하고 `info --json`으로 생성 구성을 확인한다.
2. 앱 내비게이션, 시스템 테마, 반응형 뼈대, mock API와 데이터 adapter를 만든다.
3. 홈·즐겨찾기·탐색·통합검색을 연결한다.
4. 아티스트 상세 3개 탭과 가사·공연 팝업을 구현한다.
5. YouTube 플레이어와 세트리스트를 연결한다.
6. 캘린더와 최소 설정 화면을 구현한다.
7. transitions-dev 모션을 적용하고 실제 화면을 검증한다.

완료 기준:

- 모든 주요 링크와 버튼이 목적지 또는 상태 변화로 이어진다.
- 새로고침과 뒤로가기 후 검색·탭·팝업 상태가 일관적이다.
- 즐겨찾기 변경이 홈과 캘린더 범위에 즉시 반영되고 다시 열어도 유지된다.
- 세트리스트 클릭이 실제 영상의 올바른 시점으로 이동한다. 임베드 불가 상태도 안내한다.
- 아티스트명·원곡명·원곡 아티스트명 각각으로 검색 가능하고 세트리스트 결과에서 정확한 라이브·시점으로 이동한다.
- 캘린더에는 온라인 일정·티켓 마감이 섞이지 않는다. 월 경계와 생일 연간 반복을 검증한다.
- 로딩·빈 상태·오류·깨진 이미지·긴 제목이 디자인을 무너뜨리지 않는다.
- 타입 검사와 빌드를 통과한다. 검색, 즐겨찾기 저장, 캘린더 날짜, 세트리스트 탐색 등 핵심 행동을 대상으로 검증한다.
- 모바일·PC, 라이트·다크, 키보드·reduced-motion에서 확인한다.

## 9. 제안 기본값

- 주요 범위·테마·콘텐츠·영상·검색 질문의 답변은 모두 확정됐다.
- 제안 기본값: 캘린더는 즐겨찾기 범위로 시작, 전체 보기 가능.
- 제안 기본값: 설정 1차 범위는 테마 선택만. 추가 설정은 이후 결정.
- 제안 기본값: 한국어 UI, 원어 이름과 제목 병기, 표시 시간대 Asia/Seoul.

세트리스트 검색 결과는 아카이브 썸네일을 사용한다. PC는 곡 원어명(한국어명) / 원곡 아티스트 원어명(한국어명), 다음 줄에 가창자 원어명(한국어명)을 표시하고 오른쪽에 아카이브 제목과 날짜를 표시한다. 한국어명 미등록 또는 영어 원어명에는 한국어 괄호를 생략한다. 모바일은 곡 원어명 / 원곡 아티스트 원어명 / 가창자 원어명·날짜의 3줄이다. 클릭은 곡 시작 시점으로 연결한다.
향후 데이터 계약은 아티스트 원어명·한국어명과 검색 전용 별칭 배열(영어 이름·별명)을 분리한다. 곡과 원곡 아티스트도 원어명·선택적 한국어명을 저장한다. 현재 mock의 name/display_name/roman 및 song_title(_ko)/original_artist(_ko)를 표시용으로 사용하며 백엔드 스키마는 변경하지 않는다.

## 활동량 통계
통계 탭 상단에 한국 시간 기준 월별 아카이브 개수 막대그래프를 표시한다. 6M(기본)·12M은 이번 달을 포함하며 All은 첫 기록부터 이번 달까지다. 세트리스트 유무와 관계없이 아카이브를 집계하고 빈 달은 0으로 표시한다. 기간 내 합계와 월별 툴팁을 제공하며 접근성용 표를 함께 제공한다. 기존 원곡 아티스트 섹션 제목은 아티스트 순위로 변경한다.

활동량은 영역 차트(윤곽선과 반투명 채움)로 변경했다. HACHI에 최근 18개월의 합성 아카이브 174개를 추가하여 월별 변화가 보이도록 한다. 생성 데이터는 is_sample로 구분하고 실제 영상 ID를 부여하지 않는다. 세트리스트는 비워 기존 곡·아티스트 순위에는 영향을 주지 않는다. 영상 미등록 항목은 재생 링크를 제공하지 않는다.

PC 캘린더는 120px 날짜 행 6개로 높이를 고정하고, 범위 선택 오른쪽 버튼으로 같은 높이의 월 일정 리스트를 전환한다. 연월·필터·월 이동은 공통 상단에 유지한다. 날짜 선택 시 Dialog에 해당 날짜 일정을 표시하며 기존 하단 목록은 모바일에서만 유지한다. 일정은 outline 배지와 기존 반경으로 표시한다.

- PC 캘린더 날짜 칸은 최소 136px로 일정 3개와 추가 개수·하단 여백을 확보한다. 화면 높이에 따라 늘어나되 너비 기반 비율 상한을 적용한다. 실제 칸 높이를 관찰해 표시 개수를 조절하고 넘칠 때만 `+n`을 표시한다. 리스트 모드는 콘텐츠 높이를 따른다. 2026년 9월 20일은 5개 일정으로 밀집 상태를 확인한다.
