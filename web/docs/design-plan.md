# 새 프론트 화면 설계

기준: 2026-09-18. 초기 계획과 후속 변경을 현재 구현 기준으로 통합했다. 실행은 [README](../README.md), 데이터 계약은 [API v2](../../docs/read-api-v2.md), 미지원 기능은 [후속 작업](../../docs/backend-roadmap.md), 검증은 [QA](qa.md)를 따른다.

## 범위와 디자인 기준

- Vue 3 + TypeScript + Vite + Vue Router. 기존 web.bak의 화면·스타일을 참고하거나 재사용하지 않는다.
- CLI의 --preset a2vfHFI로 생성한 shadcn-vue Luma/Neutral/Lucide 구성을 유지한다. 폰트는 src/style.css에서 Pretendard JP Variable로 변경했으며, components.json의 Inter 값은 초기 프리셋 기록이다.
- 컴포넌트 구조·접근성·색상·폰트·반경은 shadcn-vue, 호환되는 모션은 transitions-dev를 따른다. 충돌 시 shadcn-vue 우선.
- 의미 기반 색상 토큰과 사진·앨범 아트를 사용한다. 홍보 슬로건·가짜 계정·장식용 날짜를 넣지 않는다.
- 기기 테마가 기본이며 설정에서 시스템/라이트/다크를 선택한다.
- 실제 API가 기본이다. API 오류·미지원 데이터를 목업으로 보충하지 않는다. 목업은 별도 실행 모드다.
- UI의 샘플·가상 안내 배지는 제거했지만 [콘텐츠 출처](content-sources.md)에 사실과 합성 자료의 구분을 남긴다.

## 내비게이션과 프로필

홈·탐색·캘린더·설정 네 메뉴다. 1024px 이상은 아이콘+텍스트 사이드바, 769~1023px는 큰 아이콘 사이드바, 768px 이하는 아이콘 전용 하단 독이다. 모바일 공통 top bar는 없다.

독은 선택 배경을 이동시키며 현재 아이콘에 별도 볼드를 넣지 않는다. 접근성 이름·aria-current·키보드 포커스·safe area를 유지한다. reduced-motion에서는 움직임을 줄이거나 제거한다.

프로필은 공통 ArtistAvatar의 1:1 둥근 사각형이다. radius-xl(현재 14px)을 사용하고 일반 Avatar의 원형 기본값은 변경하지 않는다. 이름은 고정 크기·줄 높이와 한 줄 말줄임을 사용한다. 이름별 자동 축소와 툴팁은 없다. 하트는 별도 고정 영역으로 줄바꿈을 막는다.

목표 이름 계약은 원어 메인 / 한국어 서브 / 검색 전용 별칭이다. 목업은 이를 표시한다. 실제 DB의 display_name은 한국어 전용이 아니므로 현재는 표시 이름으로 가정하지 않고 별칭 검색에 활용한다.

## 홈·탐색

홈은 작은 브랜드·통합검색·즐겨찾기로 구성한다. 홈 카드의 삭제 하트는 없고 탐색·상세에서 즐겨찾기를 바꾼다. PC는 고정 간격으로 중앙 정렬한다. 모바일은 그리드 전체를 가운데 두고 마지막 행은 왼쪽부터 채운다. 폭이 허용하면 한 줄 4개보다 더 배치하고 여러 행 사이 간격을 컴팩트하게 유지한다.

실제 모드의 초기 즐겨찾기는 비어 있다. 실제/mock localStorage 키를 분리한다.

탐색은 즐겨찾기 우선·이름 오름차순이다. 하트를 눌러도 현재 목록 순서는 유지하고, 탐색 페이지에 다시 들어올 때 변경된 즐겨찾기 기준으로 정렬한다. 검색창은 Enter 후에도 입력을 유지한다. 격자는 모바일 3열, 중간 폭 4~5열, PC 최대 6열이다. 상세 이동과 즐겨찾기는 독립적으로 조작한다.

소속사 필터는 셀렉트다. 769px 이상에서는 왼쪽 필터와 오른쪽 최대 364px 검색창을 한 줄에 둔다. 좁은 폭에서는 필터가 160px 이상 유지되도록 검색창을 줄인다. 768px 이하에서는 검색창을 첫 줄에, 아티스트 수와 필터를 다음 줄의 양끝에 둔다. 아티스트 수는 필터의 아래쪽에 맞추고 목록과는 20px 간격을 둔다. 결과 수가 바뀌어도 필터 위치가 움직이지 않도록 열 너비를 유지한다. 셀렉트를 열 때 본문 스크롤을 잠그지 않으며, 데스크탑은 결과 길이에 따른 스크롤바 변화에도 페이지의 가로 위치를 고정한다.

다른 탭이나 상세 화면에서 탐색으로 돌아올 때는 아티스트 목록을 렌더링한 뒤 저장된 스크롤 위치를 즉시 복구한다. 로딩 골격 높이를 기준으로 복구하지 않는다.

## 검색

아티스트 이름·별칭, 세트리스트의 곡명·원곡 아티스트를 검색한다. 라이브 제목·공연명은 검색 범위 밖이다. 검색어는 URL에 유지하고 검색 결과에서는 홈 메뉴를 활성으로 표시한다. 세트리스트는 실제 API에서 50개씩 더 보기로 가져오며 가창자·원곡자 필터는 현재 불러온 결과에 적용한다.

왼쪽에 아카이브 썸네일, 오른쪽 끝에 이동 화살표를 둔다.

| 줄 | PC | 모바일 |
| --- | --- | --- |
| 1 | 원어 곡제목 － 원어 아티스트 | 동일, 넘치면 말줄임 |
| 2 | 한국어 곡제목 - 한국어 아티스트 | 동일, 넘치면 말줄임 |
| 3 | 가창 아티스트 (한국어 표기) | 가창 아티스트 · 아카이브 날짜 |
| 우측 별도 | 아카이브 제목 / 날짜 | 숨김 |

원어 구분자는 전각 －(U+FF0D), 양옆 한 칸 공백이다. 한국어가 없으면 해당 자리에도 원어를 표시한다. 한국어 줄은 가장 낮은 텍스트 계층이다. 가창자 한국어 병기는 값이 있는 PC에서 표시한다. 모바일 검색 제목 아래 설명은 숨긴다. 행 선택은 해당 영상의 곡 시작 시점으로 연결한다.

## 아티스트 상세

프로필·이름·등록된 주요 링크·즐겨찾기 아래에 **라이브 → 통계 → 오리곡 → 공연 정보** 순서로 탭을 둔다. 모바일 관련 링크는 왼쪽 정렬한다. 리소스별 로딩·오류를 분리한다.

아티스트 상세의 `뒤로가기` 버튼은 상세 탭을 이동했더라도 들어온 홈·탐색·검색 결과의 URL과 스크롤 위치로 돌아간다. 직접 진입한 경우에는 탐색으로 이동한다.

- **라이브:** 최신순 16:9 썸네일, 날짜·등록된 길이. 카드에는 날짜와 세트리스트 곡 수를 `・`로 구분해 한 줄에 표시하고, 곡 수가 없으면 `준비중`으로 표시한다. 실제 API는 처음 6개와 더 보기 6개씩 가져오고 목록에 전체 세트리스트를 싣지 않는다.
- **통계:** 월별 활동량 영역 차트, 부른 곡, 아티스트 순위. 활동량은 6M/1Y/All, 시작·끝 X축, 최대값 위 여유를 둔다. 기간 합계 설명과 라이브 기록 요약은 표시하지 않는다. 집계 기준은 API 문서에서 관리한다.
- **부른 곡:** 곡/원곡자 검색, 많이·적게·최근·오래전에 부른 순 정렬. 전체 횟수 기준 순위·곡/원곡자·최근 가창일·강조한 횟수를 10행씩 표시한다. 모바일 정렬은 제목 오른쪽이다. 동작 없는 행·헤더는 hover 배경이 없다.
- **아티스트 순위:** 전체 원곡자를 10명씩 표시한다. 횟수·전체 가창 대비 비율과 가로 막대를 제공한다. 곡/아티스트 페이지는 독립적이고 페이지 버튼은 중앙 정렬한다.
- **페이지 높이:** 통계 페이지들을 같은 grid 영역에 두어 최대 자연 높이를 유지한다. 비활성 페이지는 hidden/inert/aria-hidden으로 즉시 숨겨 스크롤 이동과 이전 막대 잔상을 막는다.
- **오리곡:** PC 왼쪽 앨범·오른쪽 수록곡, 모바일 가로 앨범·아래 수록곡. 선택한 앨범만 조회한다. 가사는 저장된 원문·번역·발음·출처·검토 상태를 표시하며 생성 요청은 하지 않는다.
- **공연:** 예정 목록과 과거 타임라인. 팝업에서 날짜·장소·가격·등록된 링크를 표시한다. 티켓은 외부 링크만 연다.

## 라이브 뷰어

PC는 영상·세트리스트를 나란히, 모바일은 위아래로 배치한다. 실제 YouTube IFrame API를 사용하며 진입 시 자동재생을 요청한다. 브라우저가 소리 있는 자동재생을 막으면 음소거로 한 번 시도하고 안내한다. 성공 여부는 브라우저 정책에 따라 달라진다.

URL t 값으로 시작하고 곡 선택 시 seekTo·URL·현재 곡 표시를 맞춘다. 실패·준비 시간 초과에는 재시도와 해당 시점의 YouTube 원본 링크를 제공한다. 영상 ID 없는 합성 아카이브는 재생 링크가 없다. 페이지를 벗어나면 재생을 정리하며 미니 플레이어·지속 재생은 없다.

뷰어의 `뒤로가기`는 통합검색 결과에서 들어온 경우 검색어가 유지된 결과 페이지와 스크롤 위치로 돌아간다. 뷰어 URL에 직접 들어온 경우에는 해당 아티스트의 라이브 목록으로, 아티스트 연결도 없으면 탐색으로 이동한다.

## 캘린더

오프라인/하이브리드 공연과 생일을 다룬다. 실제 모드는 생일 계약이 없어 생일 필터·일정을 표시하지 않는다. 온라인 방송·티켓 마감은 제외한다.

공통:

- 기본 5주, 필요한 달만 6주. 격자에 보이는 앞뒤 달 날짜에도 일정이 있으면 표시하고, 다른 달 일정은 존재만 알 수 있도록 낮은 투명도로 표시한다.
- 날짜 숫자는 작은 배경 정보로 두고 빈 곳을 포함한 칸 전체로 선택한다. 선택 후 모서리 반경이 바뀌지 않는다.
- 일정 배경은 아티스트의 유효한 theme_color를 카드 배경과 섞어 라이트·다크 모드에 맞는 연한 색으로 표시한다. 글자는 카드 전경색을 쓰고, 아티스트 색상이 없으면 기본 보조색을 섞는다. 공연 표기는 ‘아티스트 이름 공연’이다.
- 날짜 칸의 일정 이름이 길면 말줄임표 없이 칸 끝에서 잘라 표시한다.
- 실제 칸 높이만큼 일정을 표시하고 넘칠 때 하단에 작은 +N을 둔다. +N에는 독립 클릭·hover 효과가 없다.
- 날짜 선택 시 ‘일정 리스트’ 팝업에서 전체 항목을 본다. PC Dialog, 모바일 Drawer다.
- 생일 일정의 리스트 제목은 원래 이름을 유지하고, 등록된 한글 표시명이 있으면 보조 문구에 ‘한글 표시명 생일’을 쓴다. 생일 일정에서 아티스트로 이동한 뒤 ‘뒤로가기’는 진입한 캘린더 월로 돌아간다.
- 캘린더/리스트 전환은 상단을 유지하며 선택한 보기 상태는 브라우저에 저장한다. 리스트는 콘텐츠 높이를 따른다. 일정 항목의 프로필 이미지는 64px로 두고 행 안에서 위아래 여백을 확보하며, 종류·제목·보조 문구는 비슷한 높이로 이미지 옆에 배치한다. 별도 하단 날짜 패널·한국시간 안내는 없다.
- 월 이동 중에는 연월·요일·날짜 격자와 조작 버튼을 유지한다. 로딩 문구 없이 이미 받은 일정은 계속 표시하고 실패 시 달력 안에서 재시도한다. 공연 조회는 표시 중인 달의 이전 달 시작일(포함)부터 다음다음 달 시작일(제외)까지 3개월을 요청한다.
- 이전/다음 달 버튼은 PC·모바일 모두 이동 방향으로 달력 내용을 밀어내고 새 달을 반대편에서 들여온다. 전환 중 중복 입력을 막고 모션 감소 설정에서는 즉시 바꾼다.

PC는 카드가 가로 한 줄 전체를 차지한다. 카드 상단은 왼쪽 공연/생일, 중앙 연월, 오른쪽 오늘·이전/다음 달이다. 페이지 제목 옆에는 아티스트 범위·보기 전환을 둔다. 날짜 행 최소 136px에서 화면에 맞게 늘어나되 칸 너비 대비 약 1.584배 상한을 둔다. 최소 높이가 들어가는 화면에서는 바닥 여백까지 고려해 불필요한 세로 스크롤을 막는다.

모바일은 바깥 카드를 없애고 좌우 12px 여백을 둔다. 제목과 즐겨찾기/전체·리스트/캘린더 버튼은 같은 줄이다. 연월 양옆의 테두리 없는 ghost 이전/다음 달 버튼과 수평 드래그가 실시간 반영되는 스와이프·스냅을 함께 사용한다. 리스트 보기에서도 항목이 적거나 없어도 달력 격자에 해당하는 높이까지 스와이프할 수 있다. 작은 공연/생일·오늘 버튼을 배치하고 요일 헤더도 컴팩트하게 둔다. 날짜 격자 마지막 줄에는 아래 테두리를 두며 오늘 칸은 일반 칸보다 약간 다른 배경색으로 표시한다. 날짜 칸의 모바일 생일 일정은 아이콘 없이 ‘아티스트 이름 생일’로 표시한다.

모바일은 5행/6행에 같은 전체 가용 높이를 사용한다. 날짜 격자 최소 348px(6행에서 일정 1개와 +N)이며 독 실측 높이 + 독 아래 여백의 두 배를 남기고 화면에 맞춰 늘어난다. 최소 높이보다 작은 화면은 스크롤한다. 5행 4개/6행 2개처럼 일정 수를 고정하지 않는다.

## 설정·접근성·모션

설정은 시스템/라이트/다크 테마만 제공한다. 미구현 계정·동기화 옵션을 표시하지 않는다.

팝업의 제목·키보드·Escape·포커스 복귀, 긴 내용 내부 스크롤을 유지한다. 로딩은 콘텐츠 형태에 맞는 Skeleton, 빈 상태·오류는 ResourceState를 사용한다. 이미지 fallback과 긴 이름 말줄임을 제공한다. 탭·정렬·팝업을 별도 UI 시스템으로 만들지 않는다. 모션은 공통 토큰과 reduced-motion을 따르고 컴포넌트 모션과 중복 실행하지 않는다.

## 경로

| 경로 | 용도 |
| --- | --- |
| / | 홈 |
| /explore?q=... | 탐색 |
| /artists/:id?tab=lives | lives/statistics/originals/concerts |
| /lives/:id?t=... | 뷰어·시점 |
| /search?q=... | 통합검색 |
| /calendar?month=YYYY-MM-DD | 월 첫날을 나타내는 URL |
| /settings | 테마 |

가사·공연 팝업은 query 상태로 열고 새로고침·직접 접근·뒤로가기를 지원한다. 상세/뷰어의 활성 메뉴는 탐색이다.

기존 design-audit.md와 luma-audit.md의 지속적인 기준은 이 문서로, 검증 범위는 [QA](qa.md)로 통합했다. 당시 [Luma 레지스트리 자료](luma-registry-audit.json)는 근거로 보존한다.
