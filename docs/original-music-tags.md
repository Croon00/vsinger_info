# 오리지널 곡 장르·분위기

최종 확인 2026-11-23 · 조사·검증 경위는 문서 끝 [변경 이력](#변경-이력)에 있다.

오리지널/발매 음원 탐색에 곡별 장르·분위기 태그와 복수 선택 필터를 제공한다. 조회 전용이며 화면에서 태그를 수정하지 않는다. J-Pop·애니송·보컬로이드 같은 시장/출처 분류는 추가하지 않는다.

## 근거와 저장

`app/resources/classification/original_music_tags.json`은 [`app/schemas/music_tags.py`](../app/schemas/music_tags.py)의 Pydantic 모델로 검증하는 검수 목록이다(현재 40항목). 태그마다 출처 URL과 240자 이하의 근거 문구를 보존하며, 게시하는 모든 태그에 자기 근거가 있어야 한다.

- 공식 발매 소개, 아티스트 공식 사이트의 곡별 설명, 유통사가 제공한 버전명/트랙 목록을 근거로 사용한다.
- 크레딧에 피아노 연주자가 있다는 이유로 피아노 중심이라고 분류하거나, 가사·곡명·아티스트 성향·앨범 장르만으로 곡의 장르나 분위기를 추정하지 않는다.
- 어쿠스틱/피아노 버전 명시는 해당 버전에만 적용한다. 다른 공연만의 편곡을 스튜디오 음원에 옮기지 않는다. 미분류 곡을 잘못된 곡으로 취급하지 않는다.

항목은 공식 YouTube ID 또는 `recording:<id>` 중 정확히 하나로 식별한다. 영상이 없는 음원은 `recording:<id>`와 곡명·아티스트 일치 조건을 함께 검사한다. 이름으로 레코드를 병합하지 않는다. 영상 연결 후에는 영상 ID 기준으로 재검수해야 한다. 이 목록은 현재 카탈로그에 대한 검수 자료이며 다른 DB로 ID만 복사하면 안 된다.

DB 마이그레이션 없이 검수 파일을 SQL `jsonb_to_recordset`으로 읽어 오리지널 집계 결과에 연결한다. 필터는 페이지·전체 건수 계산 전에 적용한다. 파일은 수정 시각별 캐시를 사용하며 조회 중 provider·LLM·수집·DB 변경을 실행하지 않는다. 배포 시 `app/resources/classification/`을 백엔드와 함께 포함해야 한다(가변 데이터 디렉터리와 분리하려고 앱 내부에 둔다).

파일이 없으면 오류 로그를 남긴다. 장르·분위기 필터가 없는 곡 조회는 빈 태그로 기존 DB 목록을 반환하고, 분류 필터가 있으면 잘못된 0건 대신 HTTP 503을 반환한다. 파일을 복구하면 재시작 없이 다음 조회에서 다시 읽는다. 다른 파일 오류나 schema 검증 실패는 이 처리에 포함하지 않는다. 요구사항은 [014-original-song-availability](../specs/014-original-song-availability/spec.md)에 있다.

## 계약

- `GET /api/explore/music-tags`: 인증된 조회. `genres,moods` 각각 `{value,label}` 배열을 반환한다.
- `GET /api/explore/songs?kind=original&genres=rock&genres=ballad&moods=calm`: 반복 쿼리로 복수 선택. 같은 분류 안은 OR, 장르와 분위기는 AND다. 미분류 곡은 선택 필터가 없으면 표시한다. 다른 곡 종류에 음악 필터를 지정하거나 미등록 태그를 쓰면 422다.
- 항목의 `genres,moods,music_tag_sources`는 배열이며 기존 필드를 유지한다. 화면은 첫 출처를 ‘분류 근거’ 링크로 표시하며 API에는 태그별 근거 전체가 있다.
- 프론트 URL은 반복 `song_genres,song_moods`를 쓴다. 검색·정렬·소속사·아티스트·기간·더보기와 결합한다. 곡 종류 변경 시 음악 필터를 해제한다.

장르: 팝, 발라드, 록, 얼터너티브 록, 하드 록, 메탈, 재즈, R&B, 포크, 일렉트로닉, 펑크(Funk), 디스코, 어쿠스틱, 피아노 중심, 밴드, 오케스트라.

분위기: 잔잔한, 치유되는, 따뜻한, 신나는, 힘찬, 애절한, 몽환적인, 어두운, 웅장한, 밝은. 선택지가 있다고 분류된 곡이 반드시 존재하는 것은 아니다.

## 후보 수집 도구

`scripts/collect_original_music_tags.py`는 기존 영상 ID의 공개 설명만 조회해 후보 자료를 만들고 DB를 변경하지 않는다. `--review`는 별도의 OpenAI 호출이며 제안 파일만 작성한다. 제안을 검토 없이 공개 목록에 복사하지 않는다. 음성을 내려받거나 분석하지 않는다.

```powershell
.venv\Scripts\python.exe scripts/collect_original_music_tags.py --catalog db-migration/reports/original-music-tags-2026-11-15/catalog.json --output db-migration/reports/original-music-tags-2026-11-15
```

남은 작업: 미분류 항목의 공식 곡별 자료 보완, 영상 미연결 음원 조사, 음원 직접 분석이 필요한 분위기의 별도 검수 방법. 자동 정기 분류 worker와 곡별 편집 기능은 구현 범위가 아니다.

## 변경 이력

2026-11-15 최초 조사: 카탈로그 2,421항목 중 연결된 공식 YouTube 영상 686개의 공개 설명을 수집했다. 나머지 1,735항목은 연결된 영상이 없었다. 설명의 음악 관련 키워드 후보는 175개였으나 대부분 가사·크레딧·다른 작품 홍보로 확인됐다. OpenAI 자동 검토 시도는 첫 호출에서 RateLimitError로 중단되어 자동 분류 결과를 게시하지 않았다. 공식 사이트·유통사 트랙 목록을 직접 검토해 **40개 음원/편곡 버전**을 공개 목록에 반영했다. 음성을 내려받거나 청취·오디오 분석을 완료한 조사가 아니다. 분위기 분류도 명확한 설명이 있는 곡에만 제한적으로 적용했다. 수집 원문과 카탈로그 스냅샷은 Git 제외 경로 `db-migration/reports/original-music-tags-2026-11-15/`에 있다.

2026-11-15 검증: Python 계약·근거 검증 5개 통과, 기존 PostgreSQL fixture 13개는 로컬 서버 바이너리 미설치로 건너뛰었다. 실제 신규 DB는 읽기 전용으로 검증해 40개 연결이 모두 일치했다. 록 12개·발라드 4개, 합집합 16개, 잔잔한 4개, 록/발라드와 잔잔한 교집합 1개를 확인했다. 데스크톱·모바일 필터/페이지/새로고침/해제와 기존 아티스트 필터 브라우저 테스트 6개 및 프론트 빌드를 통과했다.

2026-11-21 분류 파일 누락 복구: 운영 오리지널 조회의 HTTP 500과 사용자가 제공한 `FileNotFoundError: /app/data/classification/original_music_tags.json` 로그를 확인했다. 분류 파일을 내용 변경 없이 `app/resources/classification/`으로 옮기고 누락 처리를 추가했다. 배포에서 기존 파일이 빠진 원인(빌드 누락·볼륨 등)은 아직 확인하지 않았다. 검증: 관련 Python fixture 7 passed, 로컬 PostgreSQL 의존 13 skipped. 별도 실제 통합 DB 읽기 전용 API 검증에서 기본 200·2,434곡, 록 필터 200·12곡을 확인했다. 파일 누락을 로컬 경로 교체로 재현해 기본 200·2,434곡과 록 필터 503을 확인했다. 운영 배포는 수행하지 않았으며 DB·원문·전송 상태를 변경하지 않았다.
