# 공유 YouTube 채널 — 2026-11-01

사용자가 지정한 두 공식 채널에만 다음 표시 규칙을 적용한다. 이름만으로 계정을 병합하지 않으며 원본 영상·채널 소유권·멤버의 다른 계정은 변경하지 않는다.

| 그룹·채널 | 공유 멤버 |
| --- | --- |
| VESPERBELL · `UCPd0Z22gF43dUidPYEQO5-w` | ヨミ / YOMI, カスカ / KASUKA |
| KMNZ · `UCwuS0uY-Z2Gr_5OV2oFybFA` | LITA, TINA, NERO |

`shared_youtube.py`의 명시적 규칙, 기존 `artist_group_members` 관계, 해당 그룹이 실제 소유한 위 채널 ID를 함께 확인한다. 보관된 아티스트·계정 또는 종료된 멤버 관계는 공유 대상으로 사용하지 않는다. 그룹 자체가 탐색 목록에서 숨겨져 있어도, 공개된 위 멤버의 공유 채널로는 사용할 수 있다. 다른 그룹에 자동 확장하지 않는다.

## 구독자 수와 링크

멤버 프로필과 아티스트 목록의 구독자 수·채널 생성일은 해당 공유 채널 통계를 사용한다. 개인 구독자 수로 합산하거나 복제 저장하지 않는다. 읽기 API는 nullable `youtube_statistics_source`로 그룹 이름을 반환하고 이름 옆 구독자 툴팁에도 예를 들어 `KMNZ 채널 구독자 314,000명`이라고 출처를 표시한다. 멤버의 YouTube 링크도 그룹 공식 채널을 안내하며, DB에 멤버가 채널 owner인 것처럼 새 관계를 만들지 않는다.

## 커버의 멤버별 표시

- `KMNZ TINA`, `VESPERBELL ヨミ`, 명시적 멤버 이름 괄호·covered by 표기 등 가창 명의 문맥을 확인한다. 원곡 가수인 `Tina Turner`가 제목에 있다는 이유만으로 TINA 솔로로 취급하지 않는다.
- 멤버 한 명을 명시하면 그 멤버에게만 표시한다. 두 명 이상이면 명시한 멤버들에게만 표시한다.
- 멤버가 명시되지 않았으면 사용자 지시에 따라 업로드 그룹의 대상 멤버 전원에게 표시한다. 이 기본값은 사용자 지정 표시 정책이며 개별 가창 검증이 완료됐다는 뜻이 아니다.
- 두 공유 채널 사이의 명시적 협업(예: `KMNZ LITA & VESPERBELL ヨミ`)은 명시한 두 멤버에게 표시한다. 다른 채널로 이 추론을 확장하지 않는다.
- `KMNZ LIZ`처럼 대상 밖 명의가 명시된 것을 현재 세 명의 합창으로 바꾸지 않는다. 기존 그룹 명의·원본은 보존한다.
- 제목의 커버 근거, 공개 상태, Shorts 제외 등 기존 조회 조건을 먼저 유지한다. 전체 곡 탐색에서는 같은 영상을 한 번만 표시하고, 해당 멤버 이름 검색에도 같은 표시 규칙을 적용한다. 물리적인 영상 복제나 `cover_artists` 명의 덮어쓰기는 하지 않는다.

곡 탐색의 커버 목록은 위 두 승인 공유 채널의 그룹 owner도 표시 명의에 포함한다. 그룹 자체가 아티스트 탐색에서 숨겨져 있어도 공유 채널 영상은 전체 커버 목록에서 제외하지 않으며, `VESPERBELL · ヨミ`, `KMNZ · LITA`처럼 채널 그룹명과 해당 멤버를 함께 표시한다. 개인 멤버 페이지의 분리 규칙은 그대로다. 대상 밖 명의가 붙은 영상도 그룹 채널 커버로는 전역 목록에 남지만 현재 멤버에게 억지로 배분하지 않는다. 일반 숨김 아티스트에 이 예외를 확대하지 않으며 기존 소속사·Shorts·커버 판별 조건도 유지한다.

## 수집과 갱신

현재 신규 DB에서 두 그룹의 계정 ID는 KMNZ=5, VESPERBELL=12다. 다른 DB에서는 등록 계정 ID를 먼저 확인한다.

```powershell
.venv\Scripts\python.exe scripts/refresh_youtube_channel_statistics.py --account-id 5 --account-id 12
.venv\Scripts\python.exe scripts/backfill_catalog_youtube_covers.py --account-id 5 --account-id 12 --until-complete
.venv\Scripts\python.exe scripts/refresh_youtube_video_statistics.py --account-id 5 --account-id 12
.venv\Scripts\python.exe scripts/classify_youtube_cover_formats.py --account-id 5 --account-id 12
```

표시 중 멤버가 있는 위 두 승인 그룹은 그룹의 `show_in_catalog`가 false여도 통계 갱신·수집 대상이 된다. 계정의 수집 활성 여부는 유지하며 다른 숨김 그룹을 새 대상으로 삼지 않는다. 과거 수집은 기존 체크포인트·최근 24시간 요청 카운터를 그대로 사용한다. 이번 추가 수집은 공유 채널 두 개만 선택하고 요청 간격 2초·해당 실행의 24시간 예산 2,000회로 실행했다. 도구의 기본 예산 1,500회는 변경하지 않았다. 조회 API에서는 수집·갱신을 시작하지 않는다.

## 검증

2026-11-01 실제 API로 두 채널 통계를 갱신해 VESPERBELL 367,000명, KMNZ 314,000명을 확인하고 각 멤버의 조회 값이 동일한지 검증했다. 기존 멤버/그룹 원본과 그룹 소유 관계 두 건은 유지했다. 두 채널의 과거 업로드 27페이지를 완료하고 커버 220개를 추가했으며 조회수 220개와 짧은 영상 형식 119개도 확인했다.

초기 검증은 원래 등록된 채널 ID로 저장된 영상만 대상으로 했으므로 TINA·NERO의 일반 커버가 없다는 결론은 잘못되었다. 2026-11-01 전체 업로드 목록을 다시 대조해, 목록에는 포함되어도 `videos.list.snippet.channelId`가 별도 음악 채널인 영상이 기존 동일 채널 필터에서 누락됨을 확인했다. 예: NERO `Revival`/`Stormy`, カスカ `ホログラム`, ヨミ `狭心症`.

`shared_youtube.COVER_SOURCE_CHANNELS`에 공식 업로드 목록 소속과 실제 영상 채널 ID를 함께 검증한 정확한 출처 ID만 명시한다. 해당 출처를 그룹 owner의 별도 external account로 등록하고 원래 영상의 채널 ID에 해당하는 계정으로 저장한다. 그룹 본채널 ID로 덮어쓰지 않는다. 공유 멤버 배정·전역 탐색은 이 출처들도 포함하지만, 개인 구독자 통계는 `is_statistics_source`인 기존 본채널에서만 가져온다. 원래 채널의 업로드 목록에서 이 영상들을 만나면 등록된 승인 출처로 나누어 저장하며, 승인되지 않은 외부 채널 영상은 계속 제외한다. 이름만으로 소유 관계를 추론하지 않는다.

복구 후 두 채널 전체 27페이지의 커버 후보 KMNZ 294개·VESPERBELL 287개 모두 저장됨을 실데이터로 대조했다(Shorts 후보 포함). 누락 267개를 추가하고 조회수 267개 및 짧은 영상 형식 34개를 갱신했다. 과거 라이브로 등록되었지만 출처 계정이 비어 있던 완료 커버 프리미어 1개는 정확한 API 채널 ID로 빈 출처를 연결하고 커버 행을 추가했다. 기존 라이브·가창 기록과 이미 지정된 출처는 보존했다. 같은 목록 재저장 시 추가 0개를 확인했다. `Stormy`는 NERO·ヨミ 모두에, `Revival`은 NERO에만, `ホログラム`은 カスカ에만, 멤버 표기가 없는 `Rambling Beast`는 KMNZ 세 멤버 모두에 노출됨을 확인했다. 전역 곡 탐색과 로컬 HTTP 200 응답도 확인했다.

현재 DB의 추가 출처 계정 ID는 323–329다. 조회수·Shorts 갱신 시 기존 5·12와 추가 출처를 함께 선택해야 한다. 수집은 기존 그룹 계정의 재검사로도 위 승인 출처에 나누어 저장한다. 별도 출처도 수집 활성 상태로 등록되어 이후 수집 대상이 된다. 구독자 표시는 기존 본채널을 유지한다. 회귀 테스트 36개 통과, 폐기 가능한 로컬 PostgreSQL이 필요한 7개는 미설치로 건너뛰었다. 이 fixture 검증과 앞의 실제 DB·provider 대조는 별도다(2026-11-01).
