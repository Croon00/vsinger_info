# 로컬 카탈로그 관리자

최신화: 2026-09-20. 관리자 웹과 API의 1차 구현을 완료했다. 새 Neon 카탈로그를 사용하며 기존 서비스의 DB·API·worker는 그대로 분리되어 있다. **실제 초기 음악 데이터는 아직 반영하지 않았다.**

## 실행

프로젝트 루트의 Python 가상환경과 `requirements.txt`를 사용한다. 새 접속 정보는 Git 제외 `.env.catalog`의 `NEW_DATABASE_URL`에 두며 브라우저에 전달하지 않는다.

최초 실행 또는 화면 수정 후:

```powershell
cd admin-web
npm ci
npm run build
cd ..
.\.venv\Scripts\python.exe scripts/run_admin.py
```

브라우저에서 **http://127.0.0.1:8010** 을 연다. 이후에는 마지막 Python 명령만 실행하면 된다. 종료는 실행한 터미널에서 Ctrl+C.

화면 개발은 다음 두 프로세스로 실행한다.

```powershell
# 프로젝트 루트
.\.venv\Scripts\python.exe -m uvicorn app.admin.main:create_app --factory --host 127.0.0.1 --port 8010 --no-proxy-headers --reload

# 다른 터미널
cd admin-web
npm run dev
```

개발 화면은 http://127.0.0.1:5176 이다. 기존 사용자 웹(5174/5175)의 쓰기 제한을 풀지 않았다.

## 처음 사용하는 순서

1. **검수함 → 새 검수 묶음**을 만든다.
2. **JSON 가져오기**로 파일을 선택하거나, `db-migration/input/`에 넣고 **input 폴더 불러오기**를 누른다. 직접 입력하려면 **추가**를 쓴다.
3. 목록에서 항목을 선택한다. **정보**에서 수정하고 **원본 · 변경**에서 입력 원본·수정본·출처를 비교한다.
4. 수정 후 **초안 저장**, 확인이 끝났으면 **승인**한다. 승인 성공 시 현재 검색 조건 안에서 다음 검수 대기 항목으로 이동하며 페이지 경계도 넘긴다. 보류·오류·수정 중 항목은 자동 이동 대상에서 제외하고, 다음 대기 항목이 없으면 현재 항목에 머문다. 보류·제외에는 메모가 필요하다.
5. 해당 묶음의 모든 항목을 승인 또는 제외하면 **반영 미리보기**가 활성화된다.
6. 대상 카탈로그, 포함 건수, 제외 건수와 변경 내용을 확인하고 **초기 데이터 DB에 반영**을 누른다.

초안 저장·승인·미리보기는 음악 데이터를 Neon에 쓰지 않는다. 초기 반영은 명시적으로 선택한 묶음 전체에 하나의 트랜잭션으로 수행된다. 다른 묶음은 반영 대상이 아니다. 실제 자료를 전부 한 초기 검수 묶음에 모으거나 제외/후속 범위를 먼저 정한다.

초기 반영 완료 후 일반 카탈로그 메뉴의 **추가/변경 저장**은 DB에 바로 저장한다. **검수함의 외부 플랫폼 등록 항목**은 운영 중에도 묶음 검수·반영 절차를 사용한다. 파일 기반 자료는 이후에도 검수함을 사용한다. 기존 자료는 보관/보관 해제가 가능하며 원문 문서는 생성 후 수정하지 않는다. 물리 삭제와 자동 병합은 제공하지 않는다.

## 검수 묶음 삭제

검수함에서 묶음을 선택한 뒤 **묶음 삭제 → 검수 묶음 삭제**를 누른다. 초안·승인/수정 이력·로컬 반영 기록을 삭제하며 되돌릴 수 없다. 입력 JSON과 보존된 원본 스냅샷, Neon에 이미 반영된 자료/영수증은 유지한다. input 폴더의 파일을 다른 묶음으로 다시 불러올 수 있다.

반영 중이거나 결과 확인이 필요한 묶음은 먼저 반영 이력에서 결과를 확인해야 한다. 다른 창이 묶음을 수정했다면 삭제를 거부하고 새로고침을 요구한다.

## 입력·관리 범위

28개 음악 자료 종류를 폼으로 입력하고 검색해서 연결한다.

| 메뉴 | 자료 |
| --- | --- |
| 아티스트 | 통합 명부, 별칭, 소속사, 그룹 멤버, DB에 반영된 외부 계정·계정 연결 |
| 검수함 | 외부 플랫폼 등록은 계정과 연결 아티스트를 한 항목으로 입력·검토 |
| 곡 | 곡 마스터, 원곡 아티스트 연결, 노래방 번호 |
| 라이브 · 세트리스트 | 영상, 라이브, 출연진, 가창 기록, 가창자, 원문, 출처 연결 |
| 공연 | 공연, 출연진, 티켓 일정 |
| 앨범 · 음원 | 앨범, 참여자, 녹음, 참여자, 외부 ID, 수록곡, 가사 |
| 커버 | 커버 영상, 참여자 |

관계 자료는 메뉴 상단의 자료 종류에서 선택한다. 예를 들어 곡을 만든 뒤 **원곡 아티스트 연결**에서 곡과 아티스트를 검색해 연결한다. 같은 검수 묶음의 아직 저장되지 않은 초안도 이름으로 선택할 수 있다.

- 목록 기본 30개, API 최대 100개. 초안은 생성 순서+ID, 카탈로그는 ID 내림차순.
- 검색은 각 자료의 문자 필드와 연결 대상 표시 이름을 조회한다. 범용 검색이며 유사어/중복 후보 추천은 아니다.
- 한국어 이름이 없으면 만들지 않고 비워 둔다. `is_virtual`도 미확인/예/아니요를 구별한다.
- 날짜만 아는 공연은 날짜만 저장한다. 시간대 포함 시각과 IANA 시간대를 입력하면 현지 날짜 일치도 검사한다.
- 라이브의 대표 아티스트·가창자는 그 라이브 출연진에 있어야 한다. 가창 근거도 같은 라이브 출처에 연결한다.
- 수동 등록에서는 **영상 → 라이브(대표 아티스트는 우선 비움) → 출연진 → 대표 아티스트 지정** 순서로 입력한다. 서로 연결된 자료를 함께 만들 때는 한 검수 묶음에 넣어 한 번에 반영할 수 있다.
- JSON 형식, 전체 필드와 예시는 [가져오기 규격](../schemas/import/v1/README.md)을 따른다. 기존 DB ID 대응표는 만들지 않는다.

## 외부 플랫폼 등록

DB의 `external_accounts`와 `artist_external_accounts`는 분리하고, **기존 검수 목록에서 계정과 연결 초안을 ‘외부 플랫폼 등록’ 하나의 항목으로 표시**한다. 별도 메뉴나 탭은 없다.

1. 검수함에서 묶음을 선택하고 **추가 → 자료 종류: 외부 플랫폼 등록**을 선택한다.
2. 플랫폼·주소·고유 ID·계정 이름·수집 대상 여부를 입력하고, **아티스트 추가**로 연결 아티스트를 입력한다. 각 연결에 관계, 대표 계정 여부, 표시 이름과 순서를 설정한다.
3. **계정과 연결 저장**은 로컬 SQLite 트랜잭션 하나로 저장한다. 목록에 외부 플랫폼 등록 한 항목이 생긴다.
4. 목록 항목을 선택하면 계정과 아티스트 연결을 한 편집 화면에서 확인한다. **승인** 한 번으로 포함된 계정과 연결을 함께 승인한다. 어느 하나라도 검증에 실패하면 부분 승인하지 않는다. 제외한 개별 연결은 승인 대상에서 뺀다.
5. 보류·제외·다시 검수도 항목 전체에 적용한다. 원본과 변경 내용은 같은 화면에서 확인한다.
6. 승인 후 현재 검색 조건에 맞는 다음 검수 대기 항목으로 이동한다. 실제 DB 반영은 기존 **반영 미리보기 → DB에 반영** 절차를 유지한다.

JSON으로 가져온 계정과 연결도 같은 묶음 안의 계정 참조(`$ref` 또는 수정 대상 계정 ID)를 기준으로 묶는다. 이름만으로 합치지 않는다. 연결 대상 계정 초안을 찾을 수 없는 연결은 숨기지 않고 기존 개별 검수 항목으로 남겨 수정할 수 있게 한다.

목록 검색·필터·페이지 나누기 및 화면의 검수 건수는 묶인 항목 기준이다. 저장된 연결의 **연결 제외**는 해당 초안을 반영 대상에서 제외하며, DB에 이미 있는 관계를 삭제하지 않는다.

계약: `GET /api/admin/review-items`는 묶인 검수 목록, `GET /api/admin/review-items/{id}/next-pending`는 다음 대기 항목을 반환한다. `GET /api/admin/platform-registrations/{draft_id}`는 계정·연결 초안, `POST /api/admin/platform-registrations`는 묶음 저장, `POST /api/admin/platform-registrations/{id}/review`는 전체 검수 동작이다. 기존 `/drafts`는 관계 선택과 개별 초안 API로 유지한다. DB 테이블 변경은 없다.

## 승인·반영과 오류 처리

- 원본 JSON은 해시 기반 스냅샷으로 보존하고 수정본을 따로 기록한다. 같은 묶음/파일 해시는 중복 가져오지 않는다.
- 승인한 수정 번호와 내용 해시를 저장한다. 내용이나 연결 초안이 바뀌면 해당 항목과 영향을 받는 항목의 승인을 해제한다.
- 미해결 참조, 제외된 참조, 순환 참조, 승인 후 변경을 차단한다.
- 미리보기는 대상 DB ID, 스키마 버전, 기존 값과 승인 항목을 고정한다. 이후 수정하면 계획이 만료된다.
- 최종 저장에서 DB 제약, 관계 일관성, 버전을 다시 검사한다. 미리보기만으로 모든 고유값 충돌을 확정 판정하지는 않는다. 최종 검사 실패 시 전체가 취소된다.
- 기대 버전 검사는 변경 대상/소유 부모 행을 잠근 트랜잭션에서 수행한다. 다른 창의 수정은 409로 거부한다.
- 반영 내용, 변경 이력, 작업 영수증과 초기 완료 표시는 한 DB 트랜잭션이다.
- 응답 유실이면 실패로 단정하지 않는다. **반영 이력 → 결과 확인**을 누르거나 **같은 작업 재시도**를 사용한다. 동일 작업 ID와 해시는 기존 영수증을 반환한다.
- 반영 중 결과가 불명확한 묶음은 편집을 잠근다. 수동 저장의 확인 대기 요청은 현재 브라우저 탭의 sessionStorage에 보존한다. 탭을 닫아 이 요청을 잃었으면 새로 저장하기 전에 DB 반영 영수증과 자료 목록을 확인한다.
- DB 소유자의 직접 SQL은 이 앱의 검수 정책을 우회할 수 있다.

## 구성과 저장 위치

| 경로 | 역할 |
| --- | --- |
| `admin-web/` | Vue 3/TypeScript, shadcn-vue Luma preset a2vfHFI |
| `app/admin/main.py` | 별도 API 팩토리; 기존 런타임·초기화·수집기 import 안 함 |
| `app/admin/api/` | HTTP 계약 연결, 로컬 접근·CSRF 검사 |
| `app/admin/schemas/` | Pydantic 입력 계약, 필드 메타데이터, 값 검증 |
| `app/admin/services/review.py` | 초안·승인·미리보기·반영 복구 |
| `app/admin/db/` | 공유 SQLAlchemy 풀/요청별 Session, 로컬 SQLite 저장 |
| `schemas/import/v1/` | 생성 가능한 JSON Schema와 입력 안내 |
| `db-migration/input/` | 사용자가 넣는 JSON 파일 |
| `db-migration/workspace/review.sqlite3` | 로컬 검수 장부 9개 표 |
| `db-migration/workspace/snapshots/` | 검수 원본 스냅샷 |

private 입력·작업 폴더와 빌드 산출물은 Git에서 제외한다. 설정·백업 화면에서 SQLite와 원본 스냅샷을 ZIP으로 내려받는다. 연결 문자열은 백업 대상이 아니다. 복원할 때는 관리자 서버를 종료하고 ZIP의 `review.sqlite3`와 `snapshots/`를 workspace에 함께 복구한다. 기존 workspace를 먼저 보관하고 잘못된 DB에 반영하지 않도록 설정 화면의 카탈로그 ID를 확인한다.

호스트/요청 출처와 실제 연결 주소를 localhost/127.0.0.1로 제한한다. 8시간 로컬 세션의 HttpOnly/SameSite 쿠키와 CSRF 헤더를 사용하며 CORS 공개 허용은 없다. 원문은 텍스트로 렌더링한다. 요청은 12MiB, JSON 파일은 10MiB로 제한하고 input 밖 경로·심볼릭 링크를 거부한다. 로컬 전용 세션은 다른 PC 사용자용 로그인 시스템을 대신하지 않는다.

## 실제 HTTP 계약

모든 경로 앞에는 `/api/admin`이 붙는다.

| 경로 | 동작 |
| --- | --- |
| GET /session, /connection, /metadata | 로컬 세션, 비밀 없는 DB 상태, 자료 필드 |
| GET/POST /batches | 검수 묶음 조회/생성 |
| DELETE /batches/{id}?revision={revision} | 묶음의 로컬 검수 기록 삭제 |
| GET/POST /drafts | 페이지 조회/초안 생성 |
| GET/PATCH /drafts/{id} | 원본·수정본·이력/수정 |
| POST /drafts/{id}/review | approve/hold/exclude/reopen |
| POST /imports, /batches/{id}/scan | 업로드/폴더의 JSON 가져오기 |
| GET /batches/{id}/export, /backup | 수정본 JSON/검수 백업 |
| POST /batches/{id}/preview | 반영 계획 생성 |
| POST /publish, /publish/{operation}/recover | 반영/원격 영수증 확인 |
| GET /history, /catalog/history | 로컬 계획/원격 영수증 |
| GET /catalog/{kind}, /catalog/{kind}/{id} | 실제 카탈로그 목록/상세 |
| POST /catalog/save | 초기 완료 후 수동 신규/수정 |
| POST /catalog/{kind}/{id}/archive | 보관/보관 해제 |

## 검증

2026-09-20 임시 로컬 PostgreSQL에서 관리자 통합 테스트 11개를 통과했다. 28개 자료의 생성·관계 검색, 미검수 반영 차단, 승인 해제, 파일 중복·백업, 전체 rollback, 응답 유실 복구, 수동 저장 재시도, 버전 충돌, 원격 변경 충돌, 로컬 API 접근 검사를 포함한다. 실제 Neon에는 테스트 행을 넣지 않는다.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_catalog_admin.py -q -p no:cacheprovider
cd admin-web
npm run build
npm run test:e2e
```

DB 테스트는 로컬 PostgreSQL 18 도구가 필요하다. 브라우저 테스트는 설치된 Microsoft Edge와 임시 SQLite를 사용하며 Neon 설정을 읽지 않는다. 8010 포트가 이미 사용 중이면 테스트 전에 관리자 서버를 종료한다.

## 후속 개선

현재 핵심 입력·검수·반영·수동 관리 흐름은 구현했다. 다음은 별도 개선 범위다.

- 라이브 전체 세트리스트를 한 화면에서 행 단위로 편집하고 영상 시점 재생과 함께 비교하는 전문 편집기.
- 여러 참여자를 부모 폼에서 한 번에 추가하는 입력과 신규 관계 자료의 묶음 저장 UX.
- 중복 후보 추천, 충돌 비교와 명시적 병합 도구. 이름만으로 자동 병합하지 않는다.
- 연결 자료 수정/교체 외에 개별 관계 제거 UX, 백업 복원의 웹 마법사.
- 새 DB용 사용자 조회 DTO·통계·검색 API와 `web/` 연결 전환은 2026-09-20 완료했다. 남은 조회 기능은 [백엔드 후속 작업](backend-roadmap.md)에서 관리한다.
- 실제 초기 자료의 사용자 검수·명시적 반영. Discord/Google/수집기 운영 데이터 이전은 별도 단계.

AI 정제·자동 수집·자동 승인·실제 초기 데이터 반영은 관리자 개발 과정에서 실행하지 않았다.

2026-09-20 묶음 삭제 추가 검증: 임시 SQLite에서 원본/다른 묶음 보존, 재가져오기, 오래된 수정 번호 거부, 반영 중 차단, 반영 완료 기록 삭제를 4개 테스트로 확인했다.

2026-09-20 아티스트 입력 미리보기: 상징색 입력 옆 HEX 색상 표시, 라이트·다크 일정 한 칸, 프로필 이미지 주소 아래 이미지 미리보기를 추가했다. 저장 전 입력에 반영하며 잘못된 색상과 이미지 로딩 실패를 안내한다. 일정 미리보기는 사용자 캘린더의 형태를 참고한 관리자용 색상 시안이며, 사용자 캘린더의 실제 상징색 연동은 아직 별도 작업이다. 프론트 빌드와 격리된 브라우저 테스트 2개(색상 유효성, 이미지 실패·복구, 기존 검수 흐름 포함)를 통과했다.

2026-09-20 외부 플랫폼 통합 등록 검증: 임시 SQLite·로컬 PostgreSQL에서 계정/연결 저장과 전체 취소, 중복·수정 충돌, 승인 무효화, 기존 계정 불러오기와 최종 반영을 포함해 백엔드 22개 테스트 통과. Edge 브라우저 3개 테스트에서 기존 검수 흐름과 통합 등록·승인·이탈 확인, 모바일 가로 넘침을 검증했다. 프론트 빌드 통과. 실제 Neon 음악 데이터는 테스트로 변경하지 않았다.


2026-09-20 검수 항목 통합: 별도 탭을 제거하고 기존 목록의 계정·연결을 하나로 묶었다. 승인 표기는 ‘승인’이다. 임시 SQLite·로컬 PostgreSQL 백엔드 테스트 25개와 Edge 브라우저 테스트 3개로 통합 검수·전체 취소·검색·페이지·다음 항목 이동 및 기존 반영 경로를 확인했다.
