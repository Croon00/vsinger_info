## 현재 구현

`scripts/audit_youtube_covers.py`는 기존 `.tmp/youtube-cover-backfill.json`의 catalog identity·최근 24시간 요청 이력·기존 누적 건수를 유지한다. 안정적인 `--run` 라벨로 재검사별 진행을 구분한다. 같은 라벨로 재시작하면 완료 채널·페이지를 다시 초기화하지 않는다. 매 순회에서 채널마다 최대 1페이지를 조회하므로 큰 채널 하나 때문에 다른 아티스트의 검사가 계속 밀리지 않는다. 공개 업로드 목록 끝까지 pageToken을 따라가며 각 페이지의 영상 원본 메타데이터를 확인한다. 조회 API에서 실행하지 않는다.

기존 필터·소유 관계·아카이브를 유지한다. 비어 있는 영상 출처·등록일·길이는 실제 API 채널 ID가 확인된 경우에만 채우고, 기존 비어 있지 않은 출처와 메타데이터는 덮어쓰지 않는다. 별도 게시 채널의 커버를 조용히 버리지 않고 체크포인트 `audit.foreign`에 영상 ID·게시 채널·제목·길이를 남긴다. 이름만으로 아티스트를 병합하거나 참여자를 생성하지 않는다. 비공개/삭제 등 API에서 반환되지 않는 영상을 임의 생성하지 않는다.

페이지 저장 후 순회마다 새 커버 조회수를 50개씩 갱신하고, Shorts 제목 표식을 저장한 뒤 공개 URL 형식을 최대 100개 확인한다. 새 영상이 저장만 되고 조회수 미확인/형식 대기 때문에 계속 보이지 않는 상태를 줄인다. 짧은 일반 커버는 일반 영상으로 확인된 뒤 표시하며 원본을 삭제하지 않는다. 형식이 불명인 항목은 완료로 가장하지 않고 `unknown_formats`로 보고한다. 최종 `complete`는 모든 대상의 업로드 끝 도달과 형식 미확인 없음이 필요하다. 업로드는 끝났으나 재확인 대기 형식이 남으면 `uploads_complete_formats_unresolved`로 구분한다.

명시적 `--include-disabled`는 비활성 계정도 이번 커버 읽기·저장에만 포함한다. 기존 5개 비활성 계정의 collection_enabled를 바꾸거나 일반 우타와꾸 worker·알림을 활성화하지 않는다. X·Discord·캘린더를 호출하지 않고 LLM으로 커버 후보를 일괄 분류하지 않는다.

전체 순회 중 별도 page 저장 Session과 구분되는 advisory-lock 트랜잭션이 유휴 상태로 오래 남아 첫 순회 반환 시 OperationalError가 발생했다. 각 채널·페이지에서 guard 연결을 확인하도록 보완했고, 이미 커밋된 페이지와 체크포인트를 유지해 재개했다. 일시적 DB 연결 실패는 30초 후, 공개 형식 확인 거부 등은 1시간 후 제한적으로 재시도한다. API가 Retry-After를 주면 해당 시간을 지키며, 요청 예산 소진 시 같은 이력을 기준으로 대기한다. 비밀 정보 대신 예외 종류·가능한 SQLSTATE만 로그에 남긴다.
