# 2026-11-21 모델 호출 없는 세트리스트 복구

## 원인과 사용자 예시

사용자가 제공한 https://www.youtube.com/watch?v=dSszoaOjZiY 의 실제 댓글 API 응답에서 번호 곡 목록 15개와 Ending talk·하이라이트가 구분됨을 확인했다. 기존 규칙은 타임스탬프 제목을 SetList 제목으로 인정하지 않았고, 다른 댓글의 `1曲目`처럼 곡명 없는 표기도 충돌 후보로 취급했다. 이 때문에 모델로 넘어갔으며 현재 설정된 API는 실제로 429 `credit_balance_exhausted`를 반환했다. 과거 개별 오류의 상세 코드는 저장되지 않아 당시 모든 실패의 원인이 같다고 확정하지 않는다.

댓글에 잡담이 함께 있다고 모델이 필수인 것은 아니다. 규칙이 지원하는 구조와 실제 원문 근거로 선택할 수 있는지가 기준이며, 모델 미사용 실패를 전부 모델 필수로 해석하지 않는다.

## 보강한 규칙

- `setlist-rules-2`: 명시적 타임스탬프 제목 아래 1부터 연속된 곡 번호·시각·곡정보 구분 구조가 있고 종료 또는 하이라이트 경계가 있는 목록을 추출한다. 인트로·종료·뒤쪽 하이라이트는 제외한다.
- 누락/중복 번호, 역전/중복/길이 초과 시각, 중간의 모호한 항목, 잘린 문맥, 다른 댓글의 곡 정체성 충돌은 보류한다. 곡번호만 적힌 감상 댓글은 곡명이 없는 것만으로 충돌 처리하지 않는다.
- 기존 명시적 목록에 `01|` 곡번호, 공백으로 구분된 대시 곡정보, `おはなし①` 대화 항목과 Ending talk를 지원한다.
- `セトリ＆シーン`은 명시적 구분선 앞 노래 구간만 엄격하게 검사한다. 구분선이 없거나 구간 안에 모호한 항목이 있으면 자동 확정하지 않는다.
- 원어·버전·출처 댓글을 보존한다. 구분자만으로 곡명/원곡자 순서를 추측하지 않고 원문 곡정보를 유지한다.

## 실행과 검증

`scripts/recover_rule_setlists.py` 기본 실행은 읽기 전용 조사다. `--apply`는 저장 댓글 중 규칙 선택 항목만 신규 DB에 반영한다. `--video`와 반복 `--artist`로 범위를 지정할 수 있다. 기존 활성 또는 보관 가창을 유지하고 계정·영상·archive·lease·snapshot을 다시 확인한다. 동일 request_run·추출 버전의 job key를 사용하며 실제 결과와 영상별 기록은 Git 제외 `outputs/rules-recovery-2026-11-21/`에 남긴다. Discord·Calendar·가사·번역·Spotify는 실행하지 않는다.
